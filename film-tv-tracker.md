# Film & TV Tracker — Changelog

Full version history for `film-tv-tracker.html`. As of v1.2, new entries go here in full; the inline comment in the `.html` gets a short pointer only, to avoid the file bloating.

## v1.2 (FTT-003, FTT-004, FTT-005) — Sync-chip parity, search add-as-watched, multi-select, episode tracking

Four changes, all Pete's direct request in one message.

**(1) Sync-chip parity (FTT-003).** Replaced the plain sync-dot + two collapsed Settings/Backup `<details>` panels with the suite-standard sync-chip + Data Modal, matching Fortnight Tracker v3.71 (and On Budget / Claim Tracker / Test & Issues) exactly: a tinted pill in the header (`state-local` / `state-connecting` / `state-syncing` / `state-synced` / `state-error`) that opens one modal containing a library summary, cloud sync status + Pull/Push buttons, a sync log, this app's own Preferences (bedtime threshold), storage info, and JSON backup/restore — one entry point instead of three separate UI elements. Added `slog()`/`renderSyncLog()`, `setSyncStatus()` (now folds in `window.PalSync.retryQueueLength()` the same way Fortnight Tracker does, showing "N pending sync" over a bare error while a retry is queued), `manualPull()`/`manualPush()`, and a `no-pal-banner` shown when no `PAL_SESSION` arrives within 3s. `state.lastUpdated`/`state.lastExported` are now tracked for the Storage panel. No data-model changes — purely a UI/sync-status rewrite.

**(2) Search: add to Watchlist or Watched (FTT-004a).** Each search result now has two actions — "+ Watchlist" and "✅ Add as Watched" — instead of a single "+ Add". `tmdbToTitle()` takes a `status` parameter; adding as Watched stamps `watched.date` to today with no rating/review (editable immediately after, same as any other watched title).

**(3) Watchlist multi-select + quick actions (FTT-004b).** A "☑ Select" toggle on the Watchlist tab switches cards into a selectable state (checkmark overlay instead of opening the modal on tap) with a bulk-action bar — Favourite, Mark Watched, Remove — for whatever's selected. Outside select mode, Watchlist cards also gained a quick "✅ mark watched" button alongside the existing quick-favourite star, so both don't require opening the modal. `titleCardHtml()` now takes an `opts` argument (`{selectable, showQuickWatched}`) rather than being watchlist/dashboard/watched-specific — dashboard and Watched cards render exactly as before (no `opts` passed, same click-to-open + fav-star behaviour).

**(4) Episode-level tracking (FTT-005).** A TV title's modal now has an "Episodes & Seasons" section: "Load / refresh season data" fetches every season 1..N from TMDB (`/tv/{id}/season/{n}`, one call per season, only when the user opens this — not forced on every TV title), rendered as collapsible per-season blocks with a checkbox per episode and a "Mark all watched" quick action per season. Progress (`t.seasonsProgress[season] = {episodeCount, name, episodeList, watchedEpisodes}`) is stored on the Title itself and syncs like any other title field — no separate table. Cards and the modal summary now show "N/M seasons watched" (via `seasonsWatchedSummary()`) once season data has been loaded, in place of the plain seasons count. Episode/season ticks save and sync immediately (not gated behind the modal's own Save button), consistent with how favourite/quick-watched already behave. Deliberate v1 simplifications, flagged rather than silently assumed: TMDB's `number_of_seasons` excludes "Specials" (season 0), so specials aren't fetched; a title added manually (no TMDB match) shows a note that episode tracking needs a TMDB-matched title instead of silently doing nothing.

Tested: `node --check` on both inline script blocks after every change, a full id cross-reference (no missing/duplicate ids), and an HTML tag-balance check. Not tested live in a browser: the actual TMDB season-fetch response shape (no network path to api.themoviedb.org from the build sandbox), and Supabase sync of the larger `seasonsProgress` payload — both worth a first real check.

## v1.1 (FTT-002) — Modals were unclosable

`pal-shared.js`'s own `closeModal(id)` removes an `open` class — the convention Claim Tracker/Gym Tracker use (`.modal.open`). This app copied `test-issues.html`'s `.modal-overlay.hidden` convention instead (add/remove `hidden` on the overlay), so every call to the shared `closeModal()` throughout this file was a silent no-op: it was removing a class (`open`) the overlay never had, while the class that actually controls visibility (`hidden`) was never touched. That's the exact bug behind "stuck in the modal" — Cancel, the click-outside handler, and (this release's own addition) a new ✕ button were all correctly wired, but all three called a function that did nothing to this markup. Fixed by declaring this file's own `closeModal(id)` after `pal-shared.js` loads (function declarations in a later `<script>` win over an earlier same-named one on the same global) — every existing call site needed no changes. Also added: a visible ✕ close button on both modals (the backdrop-click target was only ~16px wide on a phone — real, but too easy to miss) and an Escape-key handler as a third way out on desktop.

## v1.0 (FTT-001) — New app

New personal catalogue/watchlist/review app for Pete's Apps. Dashboard, Watchlist, Watched, Services, Search/Add and Reviews tabs. TMDB (GB region) powers search, metadata, and watch-provider availability in one call per title via `append_to_response=watch/providers` — deliberately no second API in v1; Watchmode stays a candidate only if TMDB's provider coverage proves thin in practice. Availability is always kept separate from ownership: a title shows as available/unavailable/rent-buy against the user's own Services list, never hidden when unavailable, with the missing service named on the card. Bedtime mode is derived purely from episode runtime (show-level average for v1, not a manual tag) against a configurable 20/30/45-minute threshold. Cinema release date is stored for films with a "cinema UK" Google fallback rather than a guessed "currently showing" flag. Reviews live on the Title record and surface automatically once a title is marked watched. Data model, Supabase table (`pal_film_tracker`, `title_`/`service_` prefixes, single `__settings__` row) and sync all follow the established `pal-shared.js` `table()`/`pull()`/`upsert()` pattern. Manual entry remains fully supported; TMDB is enrichment, not a dependency for opening or browsing saved data.

`pal-shared.js` also updated alongside this release: added `TMDB_API_KEY`/`TMDB_READ_TOKEN` to `PAL_CONFIG`, same precedent as `FF_PROXY_KEY`.

Tested: `node --check` on both inline script blocks, HTML tag-balance check, full id cross-reference. Not tested: live TMDB calls or Supabase sync (both needed their first real run, done since).
